# Система автоматизації діяльності митного брокера (CustomsBroker)

## 2. Інструкція з перегляду та візуалізації діаграм

### 2.1. Перегляд у середовищі розробки (IDE / VS Code)

- **Mermaid (`.mmd`)**:
  - Встановіть розширення **Markdown Preview Mermaid Support** або відкрийте файл безпосередньо у режимі попереднього перегляду Markdown/Mermaid.
  - GitHub також підтримує прямий рендеринг кодових блоків Mermaid у репозиторії.
- **PlantUML (`.puml`)**:
  - Встановіть розширення **PlantUML** для VS Code (потрібна встановлена Java або підключений сервер PlantUML) та натисніть `Alt+D` для попереднього перегляду.

### 2.2. Експорт діаграм у векторний формат SVG через CLI

Для компіляції текстових діаграм Mermaid у SVG-файли використовується Mermaid CLI:

```powershell
# Компіляція діаграми класів
npx -y @mermaid-js/mermaid-cli -i docs/class.mmd -o docs/class.svg

# Компіляція діаграми послідовності
npx -y @mermaid-js/mermaid-cli -i docs/sequence.mmd -o docs/sequence.svg

# Компіляція діаграми станів
npx -y @mermaid-js/mermaid-cli -i docs/state.mmd -o docs/state.svg
```

## 4. Наскрізна верифікація артефактів (Quality Gate)

Для підтвердження відповідності розроблених артефактів критеріям успішності SC-001 — SC-006 специфікації використовується єдиний майстер-скрипт:

```powershell
python scripts/verify_artifacts.py
```

### Критерії перевірки:
- **SC-001**: Наявність усіх 5 цільових файлів у каталозі `docs/` та суворе кодування UTF-8 без BOM.
- **SC-002**: 100% синтаксична валідність діаграм Mermaid (mmdc) та PlantUML.
- **SC-003**: Присутність 4 обов'язкових типів зв'язків у діаграмі класів (наслідування `<|--`, реалізація `<|..`, композиція `*--`, залежність `..>`).
- **SC-004**: Повна узгодженість викликів публічних методів та станів між поведінковими моделями та діаграмою класів.
- **SC-005**: Наявність 8 заповнених карток сутностей у `docs/crc.xlsx` із корпоративним стилем `#1F4E79`.
- **SC-006**: Дотримання двомовного стандарту (англійські ідентифікатори коду, україномовні описи та документація).

## 5. Відповідність Конституції проєкту

1. **KISS & YAGNI**: Модель фокусується виключно на бізнес-вимогах предметної області без зайвих ускладнень.
2. **Single Responsibility (SRP)**: Розподіл обов'язків чітко розмежовано в CRC-картках; сутності не займаються введенням/виведенням.
3. **Console Simulation**: Усі взаємодії призначені для консольної імітації без реальних зовнішніх API чи БД на поточному етапі.
4. **CLI Execution**: Усі інструменти валідації та генерації запускаються виключно через інтерфейс командного рядка.
5. **Constructor Dependency Injection**: Відносини залежності (`..>`) передаються через параметри методів або конструктори без статичного стану.
6. **Bilingual Standard**: Англійські сигнатури та типи полів/методів поєднуються з україномовною термінологією предметної області.
